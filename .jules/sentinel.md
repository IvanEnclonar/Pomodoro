## 2024-05-24 - Untrusted UserDefaults Input leading to Integer Overflow (Local DoS)
**Vulnerability:** `@AppStorage` reads directly from `UserDefaults`, which can be modified externally (e.g., via `defaults write`). The application was taking integer values (durations, limits) and string values directly from `@AppStorage` and using them in arithmetic (multiplication) and object initialization (`NSSound(named:)`) without validation. In Swift, integer overflow causes a crash. Thus, an attacker or tampered settings file could provide extremely large values that trigger an overflow crash, or arbitrary strings that consume resources.
**Learning:** UI constraints (like `Stepper(in: 1...120)`) only limit input via the app interface, they DO NOT validate the underlying data loaded from disk/`UserDefaults`. Variables annotated with `@AppStorage` must be treated as untrusted input.
**Prevention:** Always clamp `@AppStorage` integer values to safe bounds (e.g., `max(1, min(1440, value))`) before using them in calculations. Validate string inputs (like sound names) against an allowlist before utilizing them for resource access or creation.
