## 2023-10-27 - [CRITICAL] Unvalidated @AppStorage Input Leading to Potential App Crash and Unintended Behavior
**Vulnerability:** The application was directly using values retrieved from `@AppStorage` (UserDefaults) without validation. Specifically, numeric durations could be modified outside the app to cause overflow or negative timer durations, and the `completionSound` string could be modified to an invalid value, potentially leading to issues during `NSSound` initialization or playback.
**Learning:** Values managed by `@AppStorage` are external inputs and should not be inherently trusted just because they represent "internal" application state. Independent modification of `UserDefaults` by users or malicious actors can introduce invalid state into the application.
**Prevention:** Always validate values retrieved from `@AppStorage` against a known whitelist (for strings/enums) or safe boundaries (e.g., clamping numeric values to expected ranges) before using them in sensitive APIs or calculations. The pattern implemented here introduces `safe*` computed properties to act as a sanitization layer between the raw `@AppStorage` value and its usage in the application logic.
